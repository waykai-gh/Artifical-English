# English With AI Bot

Telegram-бот **Ellie** на TypeScript, grammY и PostgreSQL: свободное общение по-английски, бытовые вопросы, подробный разбор ошибок по-русски, голосовые сообщения и личный словарь.

По умолчанию: уровень B1, подробные объяснения по-русски, голосовой ответ на голосовое, доступ без ограничения по Telegram ID. Бот работает в личных чатах. История и настройки каждого пользователя хранятся отдельно.

## Быстрый запуск

Нужны Node.js 22+ и PostgreSQL. Самый простой способ поднять PostgreSQL — Docker Desktop / Docker Compose.

```powershell
npm ci
# Если .env ещё нет: скопируй .env.example в .env и заполни BOT_TOKEN и хотя бы один ключ ИИ.
docker compose up -d db
npm run doctor
npm run dev
```

PostgreSQL опубликована только на `127.0.0.1:15432`; этот порт выбран, чтобы не конфликтовать с существующими службами Windows. `DATABASE_URL` для локального Node:

```dotenv
DATABASE_URL=postgresql://english:english_local_only@localhost:15432/english
```

Схема БД создаётся автоматически при старте. Для отдельного запуска миграции: `npm run db:migrate`. Для собранного приложения: `npm run build`, затем `npm start`.

После запуска бот настраивает меню команд Telegram: в нём остаются только `/start` и `/menu`. Остальные возможности открываются через inline-меню по ходу разговора, а старые команды продолжают работать, если ввести их вручную.

На Windows собранный бот можно запустить в фоне: `npm run start:local`. Статус: `npm run status:local`, логи: `.tmp/bot.log` и `.tmp/bot-error.log`, остановка: `npm run stop:local`. Скрипт сверяет PID, время запуска и путь приложения перед управлением процессом. Остановка сначала просит приложение штатно завершить polling и дождаться активных запросов, а затем использует принудительное завершение только как запасной вариант. После изменения `.env` останови и снова запусти бота. Локальный процесс работает, пока включён компьютер; автозапуск после перезагрузки не устанавливается.

Полный запуск в контейнерах:

```powershell
docker compose up -d --build
docker compose logs -f bot
```

Внутри Compose бот обращается к `db:5432`; адрес БД из `.env` заменяется только для контейнера. Не запускай одновременно две копии с одним Telegram-токеном. `docker compose stop` останавливает контейнеры и сохраняет данные. Пароль `english_local_only` предназначен для локальной разработки; при установке на сервер задай свой `POSTGRES_PASSWORD` в `.env` до первого создания базы. Смена переменной не меняет пароль в уже созданном томе PostgreSQL.

## ИИ-сервисы и ключи

Реальные ключи выдаются в личных аккаунтах сервисов. В коде нет общих/чужих ключей. Достаточно одного работающего провайдера, остальные необязательны. Существующий `.env` поддерживается напрямую:

```dotenv
LLM_PROVIDER_NAME=groq
LLM_API_URL=https://api.groq.com/openai/v1/chat/completions
LLM_API_KEY=...
LLM_MODEL=openai/gpt-oss-120b

LLM_FALLBACK_PROVIDER_NAME=cloudflare
LLM_FALLBACK_API_URL=https://api.cloudflare.com/client/v4/accounts/ACCOUNT_ID/ai/v1/chat/completions
LLM_FALLBACK_API_KEY=...
LLM_FALLBACK_MODEL=@cf/qwen/qwen3-30b-a3b-fp8
```

Из Cloudflare URL извлекается только account ID; запросы уходят на фиксированный официальный хост. `IMAGE_MODEL` не используется: этому боту генерация изображений не требуется. Можно вместо старых названий использовать `GROQ_API_KEY`, `GROQ_CHAT_MODEL`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_CHAT_MODEL` — они имеют приоритет.

| Сервис | Возможности в боте | Где получить ключ / проверить квоту |
| --- | --- | --- |
| Groq | Диалог, Whisper для распознавания речи, Orpheus для озвучки | [Ключи](https://console.groq.com/keys), [квоты бесплатного плана](https://console.groq.com/docs/rate-limits) |
| Cloudflare Workers AI | Резервный диалог с Qwen | [Настройка REST API](https://developers.cloudflare.com/workers-ai/get-started/rest-api/), [бесплатное выделение 10 000 Neurons/день](https://developers.cloudflare.com/workers-ai/platform/pricing/) |
| Gemini | Резервный диалог и распознавание речи | [Google AI Studio](https://aistudio.google.com/apikey), [тарифы](https://ai.google.dev/gemini-api/docs/pricing) |
| OpenRouter | Резервный диалог через `openrouter/free` | [Ключи](https://openrouter.ai/settings/keys), [бесплатный маршрутизатор](https://openrouter.ai/docs/guides/routing/routers/free-router) |

Условия проверены 10 сентября 2026. Квоты зависят от аккаунта и модели, могут меняться. Для Cloudflare нужен API Token с разрешением Workers AI и account ID, а не Global API Key. На платных аккаунтах Groq/Gemini/Cloudflare наличие бесплатного выделения не гарантирует нулевых расходов: бот не меняет тариф и не управляет биллингом аккаунта. Для OpenRouter конфигурация допускает только `openrouter/free` или модели с суффиксом `:free`.

Порядок настраивается через `AI_PROVIDER_ORDER=groq,cloudflare,gemini,openrouter`. При сетевой ошибке, неверном JSON, исчерпании квоты или недоступной модели бот пробует следующий настроенный сервис. Упавший сервис получает паузу; `Retry-After` учитывается. Если все недоступны, пользователь получает понятное сообщение и может повторить запрос. Ответ и исправления получаются за один запрос к модели.

## Личный словарь

Слово или целое выражение сохраняется вместе с переводом:

```text
/save take off | взлетать, снимать
/save I couldn't help it | я ничего не мог с этим поделать
```

Разделитель — вертикальная черта `|`, поэтому пробелы и запятые можно использовать с обеих сторон. Английская часть ограничена 160 символами, перевод — 400. Повторное сохранение той же английской фразы без учёта регистра обновляет перевод и не создаёт дубликат. По умолчанию один пользователь может хранить до 1000 записей; лимит задаётся через `VOCABULARY_LIMIT`.

`/words` показывает 10 последних добавленных или обновлённых записей. Для следующей страницы используется `/words 2`. Каждая запись имеет номер: `/word 12` отправляет слово и пользовательский перевод в ИИ и возвращает значение, стиль речи, типичные сочетания, естественные примеры с переводом и распространённые ошибки. Также работает точная фраза: `/word take off`. Такой разбор расходует один запрос из дневного лимита.

`/delword 12` удаляет одну запись. `/reset` очищает только разговор и сохраняет словарь; `/forget` удаляет всё, включая словарь. Словарные записи не удаляются автоматически через 30 дней.

## Голос

1. Отправь голосовое или аудиофайл до 120 секунд и 10 МБ.
2. Бот загрузит его из Telegram, распознает через Groq Whisper; если добавлен Gemini, он доступен как резерв.
3. Покажет расшифровку, затем текстовый ответ с разбором.
4. При `/voice auto` или `/voice on` озвучит английскую часть ответа и отправит настоящий OGG Opus через `sendVoice`.

Для [Orpheus](https://console.groq.com/docs/text-to-speech/orpheus) Groq может потребовать принятия условий модели в своём dashboard. Его лимит — 200 символов на запрос: бот делит текст на части и склеивает аудио, что расходует несколько TTS-запросов на один ответ.

Если Groq TTS недоступен, включается локальная озвучка (`LOCAL_TTS_FALLBACK=true`): Windows System.Speech с установленным английским голосом или `espeak-ng` на Linux. В Docker `espeak-ng` устанавливается автоматически; при запуске Node напрямую на Linux установи пакет отдельно. Для macOS также требуется установленный `espeak-ng` в PATH. Локальный голос проще по качеству, работает без API и оплаты. `ffmpeg-static` используется для конвертации; можно задать собственный `FFMPEG_PATH`.

Бот работает с записанными сообщениями: сам включать микрофон или звонить он не умеет. Разбор строится по расшифровке, поэтому это не оценка произношения; ошибки распознавания возможны. Если любая озвучка недоступна, текст и история сохраняются.

## Управление

В нижнем меню Telegram показываются только две команды:

- `/start` — начать или продолжить практику;
- `/menu` — открыть разделы бота в любой момент.

После входа можно сразу писать по-английски. Кнопка «Мой словарь» ведёт в пошаговое добавление слова или выражения: бот отдельно попросит английскую фразу, затем перевод, сохранит запись и предложит объяснить её употребление. Настройки, голос, темы, история и удаление данных открываются из того же inline-меню. Небольшие подсказки появляются после первых сообщений, поэтому команды не нужно запоминать.

Старые команды сохранены для совместимости и принимаются при ручном вводе: `/level`, `/corrections`, `/language`, `/voice`, `/save`, `/words`, `/word`, `/delword`, `/settings`, `/reset`, `/stats`, `/privacy`, `/forget`, `/help` и `/id`.

Модель не должна выдумывать ошибки; бот дополнительно отбрасывает исправления, в которых исходная фраза отсутствует в сообщении пользователя. Исправления не гарантированно исчерпывающие: это ИИ-собеседник, а не формальная проверка всех правил. Для длинного текста с множеством ошибок лучше отправлять несколько коротких сообщений.

## Данные и эксплуатация

- PostgreSQL хранит Telegram ID, настройки, текст/расшифровку, структурированный ответ, личный словарь с переводами и состояние пошагового интерфейса. Ключи и аудиофайлы в БД не пишутся.
- Незавершённый шаг добавления слова или подтверждения удаления хранится 15 минут, после чего автоматически истекает. Повторная проверка nonce не позволяет старой кнопке изменить новые данные.
- В контекст ИИ попадают до 8 последних пар реплик в пределах 6000 символов истории плюс текущее сообщение. Объём настраивается через `HISTORY_TURNS` и `HISTORY_MAX_CHARS`; старые пары отбрасываются целиком, чтобы не раздувать запросы на бесплатных тарифах.
- Разговоры старше 30 дней исключаются из контекста сразу и удаляются при запуске и затем раз в час. Настройка: `RETENTION_DAYS`.
- Временные WAV/OGG для озвучки удаляются в `finally`. Тексты и API-ключи не выводятся в логи.
- На пользователя действует лимит 100 обращений в UTC-день и пауза 4 секунды. Неудачные попытки тоже расходуют локальный счётчик. Это ограничения бота, не квоты аккаунтов ИИ. `/forget` удаляет также локальные счётчики; это не защита публичного сервиса от злоупотреблений.
- Для ограничения доступа можно установить `PUBLIC_BOT=false` и `ALLOWED_USER_IDS=123456789`, но по умолчанию ограничение выключено по запросу владельца.
- Сообщения одного пользователя обрабатываются последовательно. Поддерживается одна запущенная копия бота; миграции защищены блокировкой PostgreSQL.
- Дубликаты успешно сохранённых Telegram update ID игнорируются. Отправка в Telegram и запись PostgreSQL не атомарны: при аварии между ними возможен повтор или потеря последнего ответа. Долговечной очереди обновлений в этой версии нет. Штатное завершение SIGINT/SIGTERM и локальная команда stop дожидаются текущих обработчиков.
- `/forget` удаляет данные только из текущей базы бота, не из Telegram, резервных копий или систем провайдеров.

## Проверки

```powershell
npm run check                 # TypeScript, тесты, production-сборка
npm run doctor                # Конфиг, PostgreSQL, Telegram, ffmpeg
npm run doctor -- --live      # Реальные короткие запросы к каждому настроенному ИИ
npm run doctor -- --audio     # Генерация OGG и обратное распознавание
```

Тесты работают без настоящих ключей и Docker. SQL выполняется в PGlite — встроенном PostgreSQL для тестирования; production использует `pg` и обычную PostgreSQL. Проверяются история, изоляция пользователей, словарь, обновление дубликатов, пагинация, настройки, очистка, лимиты, переключение сервисов, повреждённые ответы, минимальное меню Telegram, inline-навигация и пошаговый словарь, последовательность сообщений и настоящий OGG Opus через ffmpeg.

Если `doctor` показывает `429`, проверь квоту в кабинете соответствующего провайдера; регистрация второго ключа в том же аккаунте обычно не даёт новую квоту. `400` при Groq TTS часто означает, что нужно принять условия Orpheus. Если Telegram сообщает конфликт polling или активный webhook, останови прежнюю копию бота; приложение намеренно не удаляет чужой webhook автоматически.
